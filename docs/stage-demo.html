two ways it runs

    
The ambitious version, and the safe one

    
Both use the exact same Coder / Daytona / Critic pipeline underneath — they differ only in what they're allowed to do with the result.


    

      

        
Autonomous loop

        
Runs from a terminal against any repo, iterating on its own until the tests pass or it runs out of tries. Commits each approved fix inside the sandbox as it goes.

        
$ python -m autofix.cli --repo sample_repo

      


      

        
GitHub Actions review

        
Triggers on every pull request. Comment-only, never blocks a merge — but if the sandbox's tests fail, it still asks the Coder for a fix, verifies it in that same sandbox, and only then posts it.

built and broken today

    
Three real bugs this pipeline hit — and fixed

    
Proof this actually got exercised, not just written and hoped for.

    

      

        
missing conftest.py

        
pytest couldn't import the package from inside a fresh sandbox — invisible until it ran somewhere other than a developer's own machine.

      

      

        
git apply --recount

        
LLM-authored diffs kept miscounting the line totals in hunk headers, even when the fix itself was correct — plain git apply rejected every one as "corrupt" until this flag was added.

      

      

        
empty-string env vars

        
GitHub Actions renders an unset variable as "", not absent — silently defeating a naive os.environ.get(key, default) and sending an empty model name straight to Nosana.
